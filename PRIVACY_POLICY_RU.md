## Резюме

Функция «Организовать файлы» обрабатывает файлы **локально на устройстве**. Содержимое файлов **не загружается на собственные серверы издателя** для обычных операций по организации или восстановлению. Приложение **записывает локальные файлы** на устройстве (снимки сеанса, состояние возобновления, дополнительные журналы), как описано ниже.

## Данные обрабатываются локально

| Данные | Где хранится | Цель |
|------|----------------|---------|
| Выбранные вами файлы и папки | Только ваше устройство | Организация, дедупликация, исправление, возможное удаление |
| Снимок сеанса пользовательского интерфейса (`last-ui-session.json`) | `%LocalAppData%\OrganizeFilesCrossPlatform\sessions\<id>\` (рабочий стол) или личное хранилище приложения (Android) | Восстановить рабочую область: пути, расширения, параметры |
| Организовать резюме + дополнительный журнал переездов | Вывод `_OrganizeMediaLogs` или папка сеанса | Пропускать завершенные ходы; метаданные восстановления (закодированные пути) |
| Необязательный запуск пульса JSON | Вывод `_OrganizeMediaLogs` | Счетчики прогресса для внешних инструментов |
| Пробная версия / состояние лицензии | Папка профиля в разделе «Локальные данные приложения» | Обеспечьте соблюдение прав на пробную версию или сохранение |
| Состояние проверки обновлений | Папка профиля | Регулировка дополнительных проверок манифеста версии |
| Постановка Android SAF | Папка сеанса в хранилище приложений | Скопируйте деревья `content://`, чтобы движок мог их прочитать |
| Необязательный SMTP-пароль для email-уведомлений | Хранится на устройстве в настройках сеанса в зашифрованном виде (AES-GCM с файлом ключа для профиля). При обновлении, если поле присутствует, старый SMTP-пароль без AES-GCM один раз перезаписывается в AES-GCM. Файл ключа AES-GCM остается в папке профиля приложения и доступен для чтения учетной записи пользователя OS; он защищает от случайного чтения JSON настроек, но не является аппаратным хранилищем. | Только если включены email-уведомления и введены учетные данные SMTP |
